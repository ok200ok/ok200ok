  <summary><h4>1-3. 自社Webサイト用RAGチャットボット開発【2025/07 - 2025/11】</h4></summary>

##### 概要

**既存自社Webサイトのページ右下に配置する質疑応答RAGチャットボット開発**。学習・実装コストの高さによる属人化リスクや工期の増加、他サイトへの再現性確保などが最初の課題でした。これらを考慮しRAG機構本体は自前実装せずに、フルマネージドサービス`Amazon Bedrock`を選定し採用しました。結果的にFE実装とRAG機構のチューニングに注力でき、上記の課題をおよそ克服できたと思います。大まかなアーキテクチャとしては、チャットUIからのユーザー入力をAstroバックエンド経由で`Bedrock`のAPIに渡し、その返り値を1文字ずつストリーム表示するシンプルなものです。加えてRAG関連のAWS使用料金を毎日定刻にSlack通知して、コストを継続的に監視できる仕組みも`AWS Lambda`で構築しました。

筆者が単独で要件定義、調査・技術選定、実装まで全て担当したのち、応答情報源マークダウンの作成を担当するチームに引き継いで終了しました。

##### 使用技術

- **フロントエンドFE**： `TypeScript`, `Astro`, `React19`, `RadixUI(AssistantUI Primitive)`, `CSSModules`, `Slack BlockKit`
- **バックエンドBE**：`Astro APIRoutes`
- **インフラ / AWS**：`Amazon Bedrock KnowledgeBase/Agents`, `S3`, `S3 Vectors`, `IAM`, `EventBridge`, `Lambda`, `CostExplorerAPI`, `SlackAPI`, `Cloudflare Pages`(Webサイト本体)

<details><summary><h4>1-2. タスク管理＆通知社内システム開発【2025/06】</h4></summary>

##### 概要

全社的に「誰が、どういうタスクを持ち、今どういう状態にあるのか」の把握を容易にする、**Notionアプリ上に構築したタスク管理＆通知社内システム**。タスクのステータス変更およびコメント付与をトリガーとして、2秒以内に関連社員のSlackへ通知します。大まかなアーキテクチャとしては、任意のエンドポイントへHTTPリクエストを送信できる`Notion WebhookActions`という公式機能がクライアント、そのリクエストを受け取り外部API各種を叩いて情報収集と通知を行う`Hono`製の自前WebAPIがバックエンド、という構成です。

筆者は技術選択とアーキテクチャ設計**以外**の、詳細仕様策定、API本体の実装、通知UI実装、Slackチャネルアプリ実装、継続保守を担当しました。
